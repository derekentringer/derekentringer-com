# 09 — Share Sheet Integration

**Status:** Complete (Phases E.1–E.6 shipped)
**Priority:** High
**Architecture plan:** [`docs/ns/mobile-parity-arch/phase-e-share-sheet.md`](../../../mobile-parity-arch/phase-e-share-sheet.md)

## Summary

Receive text, URLs, and images from any other app via the OS share sheet → save as a new note or append to an existing one. Mobile-native; the web/desktop equivalent (paste-detection in the editor) lives separately in those apps' progress trackers.

## Sub-phases

### E.1 — Android share-sheet receiver (#560)

Wired the Android share intent through `expo-share-intent`. `app.json` registers `text/*` intent filters; the `ShareReceiverOverlay` mounts inside the authenticated tree and listens to `useShareIntentContext()`. A share text payload pops the receiver with a Save-new action. After save, `ctx.resetShareIntent(true)` clears the native module's queued payload so a subsequent share fires fresh.

### E.2 — iOS share extension (#561)

iOS share extension target generated by `expo-share-intent`'s prebuild plugin. `iosActivationRules` declares support for plain text, web URLs, and web pages. Same React component handles both platforms; no code changes needed beyond `app.json` updates.

### E.3 — Append to existing note (#562)

Adds an "Append to…" action alongside Save-new. Tapping it opens a bottom-sheet picker (`AppendTargetSheet`) of recently-modified notes with a title-search box. Selected notes get the shared text appended after a markdown horizontal rule and italic timestamp:

```
{existing content}

---

*Clipped May 8, 2026 at 9:14 AM*

{shared text}
```

`appendShareContent()` (pure helper, 13 unit tests) handles the formatting — empty existing notes skip the rule, repeated appends don't stack blank lines. The receiver was also refactored from a React Native `<Modal>` to a positioned overlay (`StyleSheet.absoluteFillObject` + `BackHandler`) so the picker's `BottomSheetModal` portal sits above the dialog instead of behind it.

### E.4 — URL preview enrichment (#563, #564, #565, plus E.4 web/desktop)

When the shared payload is a single URL, the receiver calls `GET /links/preview?url=` and renders an enriched preview card with `og:title`, description, and a thumbnail (re-hosted to our R2 CDN at `link-previews/{sha256(imgUrl)}.{ext}`, not hotlinked to the publisher).

- **Server endpoint** (`ns-api/src/routes/links.ts` + `linksPreviewService.ts`): SSRF-guarded (hostname literal-IP checks + DNS-resolution check), 5 s timeout, 2 MB HTML / 5 MB image caps, in-memory LRU (256 entries, 6 h TTL) shared across users.
- **Mobile receiver**: `classifySharedContent()` splits a `text + URL` share (Chrome's "Share with selection" payload) into `{ url, bodyText }`. The user's highlighted text renders prominently above the preview card; an enrichable URL fetches and replaces just the metadata. A "Save URL only" chip dismisses the metadata and falls back to the bare URL.
- **iOS Safari limitation accepted**: Safari's "Share with selection" sends only `public.plain-text` to share extensions — the page URL isn't included. Sharing the URL on its own works correctly. Documented as a platform constraint, not a NoteSync bug.

### E.5 — Image shares (#566)

`androidIntentFilters` adds `image/*` and `iosActivationRules` adds `NSExtensionActivationSupportsImageWithMaxCount: 1`. A media intent with an `image/*` MIME routes through the existing image-upload pipeline:

1. Resize via `expo-image-manipulator` to a 2048-px long edge JPEG.
2. Upload via `FileSystem.uploadAsync` (native multipart streamer) to `/images/upload` scoped to a freshly-created note.
3. Patch the note's content with `![]({r2Url})`.

Append-to is the same minus the create step. Server-side Claude vision generates `aiDescription` fire-and-forget. Native rebuild (`expo prebuild --platform <p> --clean`) required to regenerate the manifest / `Info.plist` with the new filter.

### E.6 — Folder picker in receiver (#567)

A Folder row sits below Content in the receiver, between the scrollable preview and the action buttons. Tapping it opens the same `FolderPicker` bottom sheet the editor uses (`mode="assign"`). Selection routes through to `createNote.folderId` for every Save-new flow — text, URL, image — so a share can land directly in "Reading List" / "Inbox" / wherever instead of always falling into Unfiled. Append-to deliberately ignores the picker since the target note already lives wherever it lives.

## UX polish

- **Editable title** seeded with the derived default (filename / og:title / first line). User edits freeze via a ref so a late-arriving link-preview fetch can't clobber the input.
- **CONTENT** label mirrors TITLE above the body area; same 4 px label/value gap.
- **Editable body** (multiline) when the share arrives with non-empty body text — quotes, plain text shares.
- **Keyboard dismissal**: tap dimmed backdrop or hit Return on the title; `keyboardShouldPersistTaps="handled"` so action buttons fire on the first tap.
- **Pending-spinner reset** on close so a second share doesn't reopen with the Save button stuck on its loading state.

## Out of scope (deferred)

- Multi-image batches (single-item v1 per the parent plan).
- Share-OUT (sharing notes from NoteSync to other apps).
- iOS Safari URL+selection parity (would require a custom JS preprocessor in the share extension; cost is disproportionate to the value).
